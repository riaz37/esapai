## Vision

### 10x Check
Not a chat widget. A salesperson that never sleeps. The assistant qualifies enterprise prospects, learns what they care about (which sections they dwelled on, what questions they asked), tailors its narrative to their intent, and converts them to a booked demo. It knows you spent 4 minutes on ERP. It notices when you visit a case study after a product page. It offers to connect you with the team at the right moment — and pre-fills the contact form with context. The sales team wakes up to enriched leads, not blank enquiries.

### Platonic Ideal
A senior enterprise buyer from manufacturing lands at 2am. The assistant greets softly, not intrusively — a neon-green orb that breathes. As they scroll to ERP, it speaks: "Manufacturing clients typically cut process time by 40% in the first 6 weeks — want to see the case study?" The buyer types: "Does it integrate with SAP?" Gets a precise answer grounded in real Sanity content. Scrolls to case studies. Assistant notices. Says: "You've now seen both the ERP product and a live deployment. Want me to set up a 20-minute call with our solutions team?" One click pre-fills the contact form. ESAP's sales team gets notified before they wake up.

This is not a UX feature. It is a proof of concept. Enterprise buyers experience the product ESAP builds for clients before they sign anything.

## API Design: /api/jarvis

Route segment config (required — Vercel serverless default timeout is 10s, Claude streaming requires up to 60s):
```typescript
export const maxDuration = 60   // Vercel Pro: 60s max. Document in CLAUDE.md as Vercel Pro requirement.
export const dynamic = 'force-dynamic'
```

```typescript
// POST /api/jarvis
// NOTE: Called only when demoMode=false. Demo mode bypasses this route entirely.
Request: {
  messages: { role: 'user' | 'assistant', content: string }[]  // max 10 messages
  section: string          // current section ID (from Section ID Registry)
  locale: 'en' | 'ar'
  visitedSections: string[]  // deduplicated, capped at 20 (see Session State Schema)
}

Response: ReadableStream (text/event-stream)
```

Security:
- **Arcjet config:** Use `lib/arcjet/jarvis-config.ts` (NEW file — separate from contact form config). Rules: `shield` + `detectBot` + `tokenBucket` (30 req/10min per IP). Do NOT use `lib/arcjet/config.ts` — that config includes email validation and contact-form rate limits.
- Arcjet rate limiting check is synchronous and completes BEFORE the stream is initiated — no partial-stream rejection edge case
- Max message length: 500 chars per message (input validation, reject 400 if exceeded)
- Max conversation history: **10 messages in API payload** (`messages.slice(-10)` before sending to Claude). The JarvisPanel UI displays the full message history — no UI pruning. Only the API payload is trimmed.
- visitedSections: max 20 items (client enforces; server ignores extras)

Prerequisites (add to package.json before implementation):
- `pnpm add @anthropic-ai/sdk` — required for streaming API route
- Add `ANTHROPIC_API_KEY` to server-side env vars in CLAUDE.md
- No PII stored server-side

RAG Context Injection:
- Sanity content is fetched using **`client.fetch()`** with Next.js cache options, consistent with all other queries in `lib/sanity/queries.ts`:
  `client.fetch(query, params, { next: { revalidate: 3600 } })`
  `@sanity/client` v6+ forwards Next.js fetch cache options correctly — native `fetch()` is NOT needed and would break type safety and project conventions.
- RAG context injected into Claude system prompt is capped at 2,000 tokens
- Only key fields are passed: title, tagline, top 3 outcomes/features, one case study reference
- Summarization is done statically in `lib/jarvis/prompts.ts` — a hand-authored template string that maps known Sanity fields to prose. No secondary LLM call.
- Full structured JSON is NOT passed raw.

Streaming + Error Signaling:
- Pre-stream errors (Arcjet 429, validation 400) return standard JSON `{ error: string, code: string }`
- Post-stream errors (Claude timeout, upstream failure) are signaled via SSE: `event: error\ndata: {"code":"upstream_timeout"}`
- Client distinguishes by checking response `Content-Type`: `application/json` = pre-stream error, `text/event-stream` = streaming (may include error event)

## Session State Schema (sessionStorage key: `jarvis_state`)

```typescript
interface JarvisSessionState {
  sessionId: string            // crypto.randomUUID() on first load, persisted
  messages: Message[]          // capped at 10 most recent
  visitedSections: string[]    // deduplicated, capped at 20 unique IDs
  announcedSections: string[]  // sections where proactive message has fired
  voiceEnabled: boolean        // user toggle preference
  sessionStartTime: number     // Date.now() on first load
}
// Generated once: sessionId = crypto.randomUUID(), stored in sessionStorage['jarvis_state']
// On tab close: sessionStorage is cleared by browser (no GDPR concern)
```

## Proactive Announcement Trigger Logic

Proactive messages fire when ALL of these are true:
1. The section enters the viewport (GSAP ScrollTrigger `onEnter`)
2. The section ID is NOT in `announcedSections` (fires once per section per session)
3. The panel is NOT currently open with an active user conversation (don't interrupt)
4. `demoMode` is false (demo mode handles section intros differently — see Demo Mode section)

When triggered: add message to `messages[]`, pulse the orb, mark section as announced in `announcedSections`.

**Proactive vs Nudge priority:** Both paths write to `announcedSections`. Whichever fires first (scroll entry proactive OR 15s nudge) wins and marks the section announced. The other is permanently suppressed for that section in the session. In practice: if user scrolls fast through a section (less than 15s), the proactive message fires on entry; the nudge never fires. If user pauses but never enters the panel, the nudge fires after 15s.

## Inactivity Nudge Logic

The 15s timer:
- Starts when a section enters the viewport (same ScrollTrigger event)
- Resets if the user types in the panel or clicks the orb within those 15s
- Fires if no interaction occurs within 15s AND the section hasn't been announced yet
- Fires at most once per section per session (same `announcedSections` guard)

## High-Intent Detection Logic

```
HIGH_INTENT = (
  messages.filter(m => m.role === 'user').length >= 2   // user asked 2+ questions
  AND visitedSections.some(s => s.startsWith('product/') || s === 'products-overview')
  AND (
    visitedSections.some(s => s === 'case-studies' || s.startsWith('case-study/'))
    OR visitedSections.length >= 4                       // saw 4+ distinct sections
  )
)

On HIGH_INTENT: append CTA message + show /contact deep-link button
Contact URL: /[locale]/contact?product={lastViewedProduct}&source=jarvis&ref={sessionId}
lastViewedProduct = last product slug in visitedSections (most recently seen, recency as proxy)
```

## Voice Output: Web Speech API

```typescript
// Browser-native, zero cost
const speak = (text: string, locale: string) => {
  if (!('speechSynthesis' in window)) return  // browser unsupported: hide toggle

  // Check Arabic voice availability before speaking in ar
  // getVoices() is async on Chromium — must wait for voiceschanged event
  if (locale === 'ar') {
    const checkAndSpeak = () => {
      const voices = window.speechSynthesis.getVoices()
      if (!voices.some(v => v.lang.startsWith('ar'))) return  // no Arabic voice installed
      window.speechSynthesis.speak(new SpeechSynthesisUtterance(text))
    }
    if (window.speechSynthesis.getVoices().length > 0) {
      checkAndSpeak()  // voices already loaded (Firefox, Safari)
    } else {
      window.speechSynthesis.onvoiceschanged = checkAndSpeak  // Chromium async load
    }
    return
  }

  const utterance = new SpeechSynthesisUtterance(text)
  utterance.lang = locale === 'ar' ? 'ar-SA' : 'en-US'
  utterance.rate = 0.9  // slightly slower for professional feel
  window.speechSynthesis.speak(utterance)
}
// Voice does NOT autoplay on first load — user must enable via VoiceToggle
// VoiceToggle is hidden when speechSynthesis is not available
// voiceEnabled preference persisted in sessionStorage (see Session State Schema)
// prefers-reduced-motion governs GSAP animations only, not voice
```

## Demo Mode (?demo=true)

When URL contains `?demo=true`:
- JarvisContext sets `demoMode: true`
- **Claude API is bypassed entirely.** All responses served from `lib/jarvis/demo-scripts.ts` (deterministic, no API latency, no cost, no hallucination risk during live sales call)
- Scripted responses are pre-authored for each section + each common question (see Appendix: demo-scripts shape)
- For questions not in the script, fallback: "Great question — let me connect you with our solutions team." + show contact CTA
- Subtle "DEMO" badge inline in `JarvisOrb.tsx` (not a separate component)
- Pre-loaded suggested questions displayed as chips in JarvisPanel
- Contact handoff CTA always visible (not conditional on high-intent)
- **Content production note:** The scripted responses in `demo-scripts.ts` require a copywriter pass before demo mode ships. Engineering delivers the scaffolding and data shape; sales/marketing team authors the final copy.
- **Demo mode section intros:** On section entry in demo mode, the scripted intro for that section is auto-appended to `messages[]` (replacing the proactive announcement flow). No nudge timer runs in demo mode.
- **Ship gate:** Demo mode is behind an env flag: `NEXT_PUBLIC_DEMO_ENABLED=true`. Default is `false`. The `?demo=true` URL param only activates if the flag is enabled.

## Performance Constraints

- JarvisProvider and JarvisOrb: dynamic import with `ssr: false` (no server render)
- Claude API calls: stream responses (text/event-stream) to prevent 30s+ timeout perception
- GSAP ScrollTrigger: `ScrollObserver` is mounted once in the root layout (inside `JarvisProvider`). Uses `usePathname()` as a `useEffect` dependency — on every route change, kills the previous `gsap.context()` and re-creates it to query fresh `[data-jarvis-section]` elements. This handles App Router's soft navigation where layout persists but page DOM changes.
- Sanity queries for RAG: see API Design section — uses native `fetch()` with `next: { revalidate: 3600 }`.
- Voice synthesis: lazy-load utterance, cancel in-progress utterance on panel close or new message
- RTL: orb position `insetInlineEnd: 24px; insetBlockEnd: 24px`. Panel opens toward `insetInlineStart`. No `left`/`right` properties.

## Reviewer Concerns (unresolved after 3 adversarial passes)

These survived 3 rounds of spec review. Resolve before implementation begins:

1. **GSAP DOM race condition — REQUIRED IMPLEMENTATION SPEC** — `querySelectorAll('[data-jarvis-section]')` may return empty if DOM isn't painted when `usePathname()` effect fires on route change. Implementation MUST use `requestAnimationFrame`:
   ```typescript
   useEffect(() => {
     ctx.revert()  // kill previous ScrollTrigger context
     requestAnimationFrame(() => {
       const sections = document.querySelectorAll('[data-jarvis-section]')
       ctx = gsap.context(() => { sections.forEach(registerTrigger) })
     })
   }, [pathname])
   ```
2. **"Active conversation" undefined** — Proactive trigger condition 3 needs a precise definition. Recommended: `isOpen && messages.filter(m => m.role === 'user').length > 0` (panel open AND user has sent at least one message).
3. **Demo mode `onEnter` path** — Two parallel paths need to be explicit: standard `onEnter` is gated by `!demoMode` check (condition 4). Demo mode registers a SEPARATE `onEnter` callback that appends the scripted intro. Not the same handler with a flag check.
4. **`visitedSections` ordering** — Array maintains insertion order (standard JS array behavior). Deduplication removes exact duplicates on append but preserves order. `lastViewedProduct = [...visitedSections].reverse().find(s => s.startsWith('product/'))`.
5. **Nudge vs panel-open** — Inactivity nudge should also check `!isOpen` before firing. If panel is open, skip nudge. Add this condition to the Inactivity Nudge Logic.
6. **Arabic TTS coverage** — Surface as explicit risk in product notes: "Arabic voice output will be silent on most enterprise Windows machines. Voice toggle should be hidden for Arabic locale unless a voice is confirmed available."
7. **`services-overview` i18n key missing** — Add to `Jarvis.sections` skeleton (known section ID, can't use default fallback).
8. **`sessionId` CRM gap** — `ref={sessionId}` in contact URL is dead data until CRM integration ships. Sales team manually notes the ref from form submission email as interim workaround. This is documented as deferred scope, not a bug.

### Affected Pages/Routes
- `/en` — orb presence, scroll triggers, proactive messages, nudge, high-intent CTA
- `/en/product/[slug]` — section-specific proactive announcement, cross-page session
- `/en/case-study/` — high-intent detection (product + case-study combo)
- `/en/contact` — deep-link URL params populated correctly
- `/en?demo=true` — demo mode (requires `NEXT_PUBLIC_DEMO_ENABLED=true`)
- `/api/jarvis` — rate limiting (429), input validation (400)

### Key Interactions to Verify
- Orb click → panel opens
- User types question → streamed response appears (not blank, not error)
- Scroll to section with `data-jarvis-section` → proactive message appears once
- 2+ questions + product + case-study visited → high-intent CTA appears
- CTA click → navigates to `/en/contact?product=...&source=jarvis`
- Navigate home → product page → messages from previous page still visible in panel
- `?demo=true` → scripted response returned, no Claude API call made

### Edge Cases
- Second scroll to same section → no duplicate proactive message
- Rate limit: >30 requests in 10min → 429 response with retry-after message
- Session on tab open → fresh session (not shared from parent tab)

### Critical Paths
- Q&A flow: orb → question → streamed answer → contact CTA → form pre-filled
- Demo mode flow: `?demo=true` → scripted intro → suggested questions → contact CTA always visible
